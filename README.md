# WildfireSimulator

Клиент-серверная система для имитационного моделирования, визуализации и анализа распространения лесных пожаров.

Проект разработан в рамках выпускной квалификационной работы:

> «Разработка имитационной модели распространения лесных пожаров с использованием графовых алгоритмов и потоковой обработки данных».

Система позволяет сформировать модель лесного массива, настроить параметры окружающей среды, выбрать очаги возгорания, запустить симуляцию и наблюдать за изменением территории и метрик в реальном времени.

> Проект является исследовательской имитационной системой и не предназначен для прогнозирования или принятия решений при реальных лесных пожарах.

## Стек

**Язык и платформа:** C#, .NET 8  
**Backend:** ASP.NET Core Web API, Entity Framework Core  
**База данных:** PostgreSQL  
**Потоковая обработка и real-time:** Apache Kafka, SignalR  
**Desktop:** Avalonia UI, XAML, MVVM  
**Инфраструктура:** Docker, Docker Compose, Bash

WildfireSimulator объединяет несколько функциональных компонентов:

- вычислительную модель распространения пожара;
- генерацию сеточных и графовых моделей территории;
- серверный REST API;
- сохранение и восстановление симуляций;
- потоковую обработку событий и метрик;
- передачу обновлений в реальном времени;

- shell-скрипты для запуска компонентов системы.

## Моделирование территории

Поддерживаются два представления лесного массива:

- регулярная двумерная сетка;
- графовая модель территории.

В сеточной модели связи создаются между соседними участками по горизонтали и вертикали.

В графовой модели:

- вершина представляет участок территории;
- ребро задаёт возможность передачи теплового воздействия;
- параметры связи учитывают расстояние и уклон;
- поддерживаются кластерные структуры и связи между отдельными областями графа.

Для участков задаются тип растительности, влажность, высота, запас топлива и текущее состояние.

Основные состояния участка:

- нормальный;
- горящий;
- выгоревший.

Вода и участки без растительности используются как препятствия, снижающие распространение огня.

## Генерация территории

Система формирует исходную модель лесного массива на основе заданных параметров:

- размеров территории;
- типа структуры;
- распределения растительности;
- начальной влажности;
- перепада высот;
- плотности горючего материала;
- количества начальных очагов;
- случайного зерна генерации.

Генератор поддерживает создание неоднородного рельефа, участков с разной растительностью, водных объектов и открытых областей без растительности.

Подготовленную модель можно просмотреть и отредактировать до запуска симуляции.

## Вычислительная модель

Распространение пожара выполняется пошагово.

На каждом шаге система:

1. определяет активные горящие участки;
2. рассчитывает интенсивность горения;
3. вычисляет тепловое воздействие на связанные участки;
4. учитывает ветер, расстояние, уклон, влажность и осадки;
5. обновляет накопленное тепло;
6. рассчитывает порог и вероятность воспламенения;
7. определяет новые возгорания;
8. уменьшает запас топлива;
9. переводит выгоревшие участки в соответствующее состояние;
10. формирует метрики выполненного шага.

Модель учитывает:

- тип растительности;
- запас топлива;
- влажность участка;
- температуру и влажность воздуха;
- скорость и направление ветра;
- интенсивность осадков;
- расстояние и уклон;
- стадию горения;
- количество источников теплового воздействия.

Один пользовательский шаг может разделяться на внутренние подшаги для более последовательного обновления модели.

## Управление симуляциями

Пользователь может:

- создать сеточную или графовую симуляцию;
- настроить территорию и погодные условия;
- выбрать случайные или ручные очаги;
- отредактировать подготовленную карту;
- запустить симуляцию;
- выполнять отдельные шаги;
- включить автоматический режим;
- приостановить или остановить выполнение;
- сбросить и повторно запустить модель;
- удалить симуляцию;
- просмотреть текущее состояние и историю метрик.

## Backend и хранение данных

Серверная часть реализована на ASP.NET Core Web API.

API обеспечивает:

- создание, получение и удаление симуляций;
- запуск и остановку моделирования;
- пошаговое выполнение;
- сброс состояния;
- получение структуры территории;
- настройку начальных очагов;
- загрузку текущего состояния и истории метрик.

В серверной части также реализованы:

- Dependency Injection;
- DTO для передачи данных;
- асинхронная обработка запросов;
- централизованная обработка исключений;
- журналирование HTTP-запросов;
- endpoint проверки состояния `/health`.

Для хранения используется PostgreSQL и Entity Framework Core.

В базе данных сохраняются:

- параметры симуляции;
- погодные условия;
- сеточная или графовая структура;
- состояния участков;
- стартовые очаги;
- текущий шаг;
- активное состояние;
- история метрик.

Сложные структуры сохраняются в сериализованном виде с использованием PostgreSQL `JSONB`.

Состояние активной симуляции может быть восстановлено после перезапуска серверного приложения.

## Потоковая обработка

После выполнения шага события и метрики публикуются в Apache Kafka.

Фоновый сервис обрабатывает поток данных и рассчитывает:

- площадь пожара;
- количество горящих и выгоревших участков;
- скорость изменения площади;
- ускорение распространения;
- скользящие средние `SMA3`, `SMA5` и `SMA10`;
- аномальные изменения показателей;
- краткосрочный прогноз площади;
- среднюю абсолютную ошибку прогноза `MAE`.

Краткосрочный прогноз строится по истории текущей симуляции с использованием линейной регрессии.

Результаты потокового анализа передаются в SignalR Hub и затем доставляются подписанным клиентам.

## Desktop-приложение

Клиент разработан на Avalonia UI с использованием XAML и MVVM.

Приложение позволяет:

- подключаться к серверному API;
- создавать и выбирать симуляции;
- отображать сеточную и графовую модели;
- редактировать подготовленную территорию;
- выбирать очаги возгорания;
- управлять пошаговым и автоматическим выполнением;
- наблюдать за распространением пожара;
- просматривать текущие и исторические метрики;
- получать прогнозы и уведомления об аномалиях;
- получать обновления через SignalR.

HTTP API используется для команд и получения сохранённых данных. SignalR используется для доставки текущих изменений без постоянного опроса сервера.

## Архитектура

Проект разделён на пять логических уровней:

### Domain

Предметные модели территории, погоды, симуляции и метрик.

### Application

Вычислительная и прикладная логика:

- расчёт распространения пожара;
- управление симуляциями;
- формирование событий;
- контракты сервисов и репозиториев;
- DTO.

### Infrastructure

Работа с внешними компонентами:

- PostgreSQL и Entity Framework Core;
- миграции и репозитории;
- генерация территории;
- Kafka producer и consumer;
- фоновые сервисы.

### API

ASP.NET Core Web API, контроллеры, SignalR Hub, middleware и конфигурация приложения.

### Client

Avalonia-приложение с XAML-представлениями, ViewModel, клиентскими моделями и сервисами взаимодействия с API и SignalR.

Основной поток данных:

```text
Avalonia Client
      │
      ├── HTTP API ──> ASP.NET Core API
      │                       │
      │                       ├── Application ──> Domain
      │                       │
      │                       └── Infrastructure ──> PostgreSQL
      │
      └── SignalR <── SignalR Hub <── обработка сообщений Kafka
                                            │
                                            └── Apache Kafka
```

## Как работает система

1. Пользователь задаёт параметры симуляции в desktop-приложении.
2. Клиент отправляет запрос в ASP.NET Core API.
3. Сервер генерирует сеточную или графовую модель территории.
4. Пользователь выбирает или редактирует начальные очаги.
5. Вычислительный сервис выполняет очередной шаг моделирования.
6. Новое состояние и метрики сохраняются в PostgreSQL.
7. События публикуются в Apache Kafka.
8. Фоновый сервис рассчитывает дополнительные показатели и прогноз.
9. Результаты передаются через SignalR.
10. Avalonia-клиент обновляет визуализацию и аналитические показатели.

## Запуск

### Требования

- .NET 8 SDK;
- Docker и Docker Compose;
- Bash;
- Git.

### Клонирование

```bash
git clone https://github.com/Idashxdx/WildfireSimulator.git
cd WildfireSimulator
dotnet restore
```

### Автоматический запуск

Основной запуск компонентов системы выполняется скриптом:

```bash
chmod +x start_full_system.sh
./start_full_system.sh
```

### Ручной запуск

Запуск инфраструктуры:

```bash
docker compose up -d
```

Docker Compose запускает PostgreSQL, ZooKeeper и Apache Kafka.

Запуск API:

```bash
dotnet run --project WildfireSimulator.API
```

Проверка API:

```text
http://localhost:5198/health
```

Запуск desktop-клиента:

```bash
dotnet run --project WildfireSimulator.Client
```

По умолчанию клиент подключается к:

```text
http://localhost:5198
```

Остановка инфраструктуры:

```bash
docker compose down
```

- Результаты не являются метеорологическим прогнозом.

- Прогноз строится только по истории текущей симуляции.
- Проект не предназначен для принятия решений при реальных пожарах.
